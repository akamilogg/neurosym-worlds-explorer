Wire contract — System 1: POST /v1/systemone with { model: "jev-latest", state: {...}, questions: {...} } → { answers: { <id>: { type: "choice", probabilities, confidence } | { type: "score", score, legend } | { type: "noul", noul } } }. The battery belongs to System 2: every declared question is accepted (a choice can be a value question that composes V(s), or a policy question whose options are the legal moves, which orders the search and never enters V(s)). The harness composes V(s) in code from those answers (Composite scoring pattern) and has no local evaluator: if Jev does not answer, the run stops. CORS (measured): api.typesafe.ai answers the preflight with 400 Disallowed CORS origin for every origin outside its allow-list, so a page cannot POST to it directly (DevTools shows only failed OPTIONS rows and the JS sees "Failed to fetch"). Run node jev-relay.js with TYPESAFE_API_KEY set, then press Use local relay - or open the harness straight from the relay at http://127.0.0.1:8787/fox-hounds-harness.html. Either way the key stays server-side, as TypeSafe advises for web apps.
Two phases: Search for the Winning Rule Set runs the learning loop (attempts x games, the Mouse opponent is fixed in code and described to Jev inside the state); the accepted rule set is then frozen and every further game measures exactly it. With a rule set in hand, New game starts a human game against that engine: click your piece, then the highlighted square (Undo steps back to your last decision). System 2 is not called during a human game and the rule set cannot change in it.
